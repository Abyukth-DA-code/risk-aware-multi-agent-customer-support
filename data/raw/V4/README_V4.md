# Capstone Customer Support Dataset — V4 (Research Ready)

## Purpose
This package supports the capstone project:
**Autonomous Multi-Agent Customer Support Resolution System with Human-in-the-Loop Escalation**
with the research direction **Risk-Aware Adaptive Multi-Agent Orchestration**.

## V4 changes from V3
1. Fixed operational-data foreign-key/semantic inconsistencies.
2. Orders are restricted to E-commerce customers.
3. Transactions inherit the exact Customer_ID of their referenced Order_ID.
4. Students are restricted to Education customers.
5. Business records are restricted to Small Business customers.
6. Support tickets now contain an explicit Domain and the Domain exactly matches the customer's domain.
7. Added operational `Integrity_Checks` and master/task `Quality_Control` sheets.
8. Expanded the data dictionary with relationship and leakage-control rules.
9. Preserved the V3 train/validation/test design and verified zero overlap with task-balanced training.
10. Kept gold confidence/autonomy fields as evaluation/reference signals; they must not be used in a way that causes target leakage.

## Data package
- `01_Master_Gold_V4.xlsx`: Core labeled cases, train/validation/test, critical safety benchmark.
- `02_Task_Balanced_Training_V4.xlsx`: Task-specific balanced training sets for risk, complexity, sentiment, and optional multi-domain classification.
- `03_RAG_Knowledge_Base_V4.xlsx`: Trusted knowledge documents with authority/version/freshness metadata and outdated evidence for conflict testing.
- `04_Operational_Data_V4.xlsx`: Synthetic customers, orders, transactions, support tickets, students, and business records.
- `05_Memory_V4.xlsx`: Synthetic short/long-term support memory.
- `06_Human_Feedback_Template_V4.xlsx`: Human review/evaluation template; fill after system runs.
- `07_Data_Dictionary_and_Label_Guide_V4.xlsx`: Definitions, label guidance, relationships, and leakage controls.

## Recommended modeling protocol
- Known single-domain deployment: use domain configuration; do not require runtime domain classification.
- Multi-domain demo: train/evaluate an optional domain classifier using `Domain_Balanced`.
- Intent/sentiment/risk/complexity: train task-specific models using only allowed input features.
- Autonomy: learn/tune the decision policy from upstream observable signals (risk, complexity, evidence quality, verification, action sensitivity, etc.). Do not use `Escalation_Required` as a shortcut target feature.
- Gold confidence fields are for evaluation/reference, not model inputs for the same prediction task.
- RAG documents are a separate knowledge source from ML training data.
- Human feedback is generated by reviewers after the AI system produces a resolution.

## Evaluation design
Compare:
1. Conventional LLM chatbot
2. Single-agent RAG
3. Fixed multi-agent workflow
4. Proposed adaptive multi-agent system

Evaluate on the same held-out cases using resolution accuracy, intent F1, unsupported-claim/hallucination rate, evidence quality, escalation effectiveness, latency, agent utilization, and human correction rate.

## Privacy
All operational records are synthetic. Do not replace them with real customer PII for the academic prototype.

## Important
This dataset is designed to be **research-ready**, not to guarantee a particular model accuracy. Final accuracy depends on model choice, preprocessing, training protocol, retrieval configuration, prompts, agent tools, and experimental design.
